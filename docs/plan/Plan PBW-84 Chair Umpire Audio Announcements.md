## Task Analysis

- Main objective: Add a match-scoped audio announcements toggle and chair-umpire scoring phrasing, using the existing match setup, current-match persistence, i18n, and speech service without rewriting the scoring engine.
- Identified dependencies: `docs/prd/chair-umpire.md`; match setup contract in `src/core/match/types.ts`, `src/core/match/validation.ts`, and `src/core/match/index.ts`; current-match record parsing in `src/lib/current-match/persistence.ts`; setup form/UI in `src/components/SetupScreen/{types.ts,useSetupForm.ts,SetupScreen.tsx,SetupScreen.module.css}`; speech types/generator in `src/lib/speech/{types.ts,message-generator.ts}`; locales in `src/lib/i18n/locales/{en,pt,es}.ts`; live screen integration in `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`; existing tests under `test/core/match`, `test/current-match`, `test/components/SetupScreen`, `test/lib/speech`, and `test/components/ActiveMatchScreen`.
- System impact: Match setup gains a new persisted boolean and legacy fallback path; Setup Screen rules card layout changes; speech payloads and translated copy expand for chair-umpire phrases; ActiveMatchScreen gains a transition-aware speech side effect; regression coverage must span validation, persistence, UI, and live match announcements.

## Chosen Approach

- Proposed solution: Extend `MatchSetup` with `audioAnnouncementsEnabled` defaulting to `true`, surface it as the first toggle in the Setup Screen rules card, keep the rules card internally scrollable using existing tokenized spacing/layout variables, enrich `generateSpeechMessage` with chair-umpire phrasing inputs (`gameMode`, correction flag, point-pressure context) while normalizing live score labels such as lowercase `ad`, and add a small ActiveMatchScreen effect that compares the previous and current match snapshot to choose the correct speech event and only call the speech service when `setup.audioAnnouncementsEnabled` is true.
- Justification for simplicity: This avoids a new global speech/event bus, avoids refactoring `useMatchSession` or the scoring engine just to expose metadata, reuses the current-match parser for backward-compatible defaults instead of introducing a schema migration, and keeps all new logic close to the existing modules that already own setup persistence, speech formatting, and live-match side effects.
- Components to be modified/created: `src/core/match/types.ts`, `src/core/match/validation.ts`, `src/core/match/index.ts`, `src/lib/current-match/persistence.ts`, `src/components/SetupScreen/types.ts`, `src/components/SetupScreen/useSetupForm.ts`, `src/components/SetupScreen/SetupScreen.tsx`, `src/components/SetupScreen/SetupScreen.module.css`, `src/lib/speech/types.ts`, `src/lib/speech/message-generator.ts`, `src/lib/i18n/locales/en.ts`, `src/lib/i18n/locales/pt.ts`, `src/lib/i18n/locales/es.ts`, `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `test/core/match/setup-validation.test.ts`, `test/core/match/test-helpers.ts`, `test/current-match/persistence.test.ts`, `test/components/SetupScreen/useSetupForm.browser.test.tsx`, `test/components/SetupScreen/SetupScreen.browser.test.tsx`, `test/lib/speech/message-generator.test.ts`, `test/components/ActiveMatchScreen/ActiveMatchScreen.browser.test.tsx`, `docs/plan/Plan PBW-84 Chair Umpire Audio Announcements.md`.

## Implementation Steps

1. Extend the match setup contract first: add `audioAnnouncementsEnabled` plus `defaultAudioAnnouncementsEnabled` to `src/core/match/types.ts`, export it from `src/core/match/index.ts`, require/validate it in `src/core/match/validation.ts`, and update `src/lib/current-match/persistence.ts` to default missing or corrupted persisted values to `true` so resumed legacy matches stay compatible. Update raw setup fixtures/helpers (`test/core/match/test-helpers.ts`, `test/core/match/setup-validation.test.ts`, `test/current-match/persistence.test.ts`, and any compile-failing setup literals) so the new field round-trips correctly. Rollback note: if legacy record parsing breaks, stop here and fix the persistence fallback before touching UI or speech.
2. Surface the toggle in the setup form and UI: add `audioAnnouncementsEnabled` to `SetupFormData`, initialize it from the new default in `useSetupForm`, add an `updateAudioAnnouncementsEnabled` handler, include the field in the `createMatchSetup` input inside `SetupScreen.tsx`, and insert a new `Toggle` at the top of the Rules card before Golden Point. Update `SetupScreen.module.css` so the Rules card scrolls internally rather than stretching the screen, reusing the existing tokenized spacing/padding from `design-tokens/component/card.tokens.json` (`component.card.rules.padding/gap`) and the shell height constraints already exposed via `Layout.module.css` / `design-tokens/app/screen.tokens.json`; avoid hardcoded spacing values that would drift from `docs/design/padelbuddyweb.pen`. Add/adjust browser tests to cover default checked state, DOM order before Golden Point, and scrollable card behavior.
3. Enrich the speech message generator for chair-umpire phrasing without changing the speech service contract more than necessary: extend `SpeechEventData` with the minimal extra context needed for formatting (game mode, correction flag, and a point-pressure hint such as game-point vs break-point), normalize both `'ad'` and `'Ad'`, change standard spoken score formatting from numeric strings to translated terms with chair-umpire separators (`Fifteen - Love`, `Thirty - All`), special-case `40-40` to `Deuce` in advantage mode and `Golden Point` in golden-point mode, prefix undo announcements with `Correction.`, and append `Game point {{teamName}}` or `Break point` when the current standard game state is one point from ending. Keep tiebreak announcements numeric and leave existing game/set/match strings intact unless tests prove they also need wording alignment. Update all three locale files with the new setup toggle labels and speech phrases, and expand `test/lib/speech/message-generator.test.ts` to cover deuce, golden point, correction, game point, break point, translated standard scores, tiebreaks, and lowercase `ad`.
4. Integrate speech in `ActiveMatchScreen.tsx` with transition-aware gating: create a file-local pure helper that compares the previous and current snapshot/projection to decide whether the latest change should announce a corrected score (`point-scored` + correction flag), a normal point-scored update, or an existing `game-won` / `set-won` / `match-won` event so game-winning points do not incorrectly announce the reset `0-0` state. Instantiate `useSpeechService`, initialize refs from the first render so nothing speaks on mount, and only call `speechService.announce(...)` when `snapshot.projection.setup.audioAnnouncementsEnabled` is true; also destroy/cancel the speech service on unmount to avoid stale utterances after route changes. Add/adjust `test/components/ActiveMatchScreen/ActiveMatchScreen.browser.test.tsx` to prove enabled matches speak, disabled matches stay silent, undo announcements include `Correction.`, and winning-point transitions choose the non-score event instead of reading the next game’s reset score. Mitigation note: if effect timing causes duplicate calls, keep the previous-action ref and event builder pure and validate it with mount/update tests before merging.
5. Finish with regression checks at the boundaries that matter for PBW-84: run the focused suites for match setup validation/persistence, setup form/screen, speech generator, and active match speech integration, then run `pnpm complete-check`. During manual verification, confirm the Rules card stays within the fixed screen shell from the Pencil design, starting a match with audio off produces no announcements, starting with audio on speaks chair-umpire terms, undo speaks `Correction.`, and resuming a legacy saved match defaults the missing flag to enabled instead of failing to load.

## Validation

- Success criteria: `MatchSetup` includes `audioAnnouncementsEnabled` with a default of `true` and it persists through current-match record creation/reload; the Setup Screen Rules card shows the new toggle first and scrolls vertically within the existing shell; `generateSpeechMessage` emits translated chair-umpire phrases for standard scores, Deuce, Golden Point, Correction, Game point, and Break point; `ActiveMatchScreen` only triggers speech when `audioAnnouncementsEnabled` is enabled and picks the correct event for score vs undo vs game/set/match win transitions.
- Checkpoints: Pre-implementation, confirm the simplest compatibility strategy is parser fallback rather than a current-match schema bump; after Step 1, validation and persistence tests must prove the new flag round-trips and legacy records default to `true`; after Step 2, setup form/browser tests must prove the toggle is present, first in order, and the rules card is scrollable with token-based spacing intact; after Step 3, message-generator unit tests must cover Deuce/Golden Point/Correction/Game point/Break point plus lowercase `ad`; after Step 4, ActiveMatchScreen browser tests must show no announcement on initial render, silent behavior when disabled, and correct speech events for score, undo, and winning-point transitions; post-implementation, `pnpm complete-check` and manual on-device/browser verification must pass before the feature is considered done.
