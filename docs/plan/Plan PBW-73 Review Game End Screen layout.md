## Task Analysis

- Main objective: Align `src/components/MatchEndScreen` with Pencil node `48SbC` by closing the confirmed visual gaps only: add the header Share placeholder, resize the trophy badge, restyle the two action buttons, and apply the Match End-specific background while preserving the existing new-match / continue behavior.
- Identified dependencies: `src/components/ui/TopBar/TopBar.tsx` already exposes a right-side children slot, so the Share control should be injected there instead of changing the TopBar API; `src/components/Layout/Layout.module.css` already reads screen-scoped background geometry variables, but its radial color is still hard-coded and must be opened up for Match End; `src/components/ui/Button/Button.tsx` is shared across screens, so Match End button styling should be overridden locally rather than changing shared size/variant defaults; `public/locales/en.json`, `public/locales/es.json`, and `public/locales/pt.json` must gain a `match.end.actions.share` key because all user-facing copy goes through `react-i18next`; `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx` is the narrowest existing test seam for the new placeholder coverage.
- System impact: The change is mostly screen-local, but it touches two shared styling surfaces (`Layout` background variables and the shared `Button` primitive) that are also used by Setup and Active Match, so the implementation must scope all overrides through Match End classes and avoid changing global tokens or shared button variants. A second non-obvious constraint is that `lucide-react` is not currently installed while `WinnerCard.tsx` already uses local inline SVG icons, so the simplest match for the Share and Trophy visuals is a local lucide-shaped SVG rather than a new icon dependency.

## Chosen Approach

- Proposed solution: Keep the current component tree and extend only the seams that already exist: render a disabled Share pill as `TopBar` child content from `MatchEndScreen.tsx`, move Match End background values onto a new screen root class passed to `Layout`, resize the existing trophy badge/icon classes in `WinnerCard.module.css`, and restyle the existing `Button` instances with Match End-specific CSS classes for `New Match` and `Continue`.
- Justification for simplicity: This reuses the current `Layout`, `TopBar`, `Button`, and `WinnerCard` structure without introducing a new screen shell, a new shared button variant, or a new icon package. Rejected alternatives: adding a Match End-specific TopBar API even though the right-side slot already exists; adding `lucide-react` for one static placeholder icon; and changing shared `Button` size/outline tokens, which would risk Setup and Active Match regressions for a screen-specific visual issue.
- Components to be modified/created: `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/MatchEndScreen.module.css`, `src/components/MatchEndScreen/WinnerCard.tsx`, `src/components/MatchEndScreen/WinnerCard.module.css`, `src/components/Layout/Layout.module.css`, `public/locales/en.json`, `public/locales/es.json`, `public/locales/pt.json`, and `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx`; conditionally `src/components/ui/TopBar/TopBar.module.css` only if the new header pill causes narrow-screen wrapping or compression during validation.
