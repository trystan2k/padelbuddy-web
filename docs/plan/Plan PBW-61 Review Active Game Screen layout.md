## Task Analysis

- Main objective: Align `src/components/ActiveMatchScreen` with Pencil node `VSRKf` by correcting the game-screen background, score panel sizing, overlay composition, panel structure, and button styling while preserving the existing scoring/session behavior.
- Identified dependencies: Shared shell styling in `src/components/Layout/Layout.module.css`; active match composition in `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `src/components/ActiveMatchScreen/ActiveMatchScreen.module.css`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.tsx`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.module.css`, and `src/components/ActiveMatchScreen/SetsCard/SetsCard.module.css`; token sources in `design-tokens/base/dimension.tokens.json`, `design-tokens/base/font.tokens.json`, `design-tokens/semantic/typography.tokens.json`, and generated output `design-tokens/dist/variables.css`; active-match browser coverage in `test/components/ActiveMatchScreen/ActiveMatchScreen.browser.test.tsx` and `test/components/ActiveMatchScreen/TeamPanel.browser.test.tsx`; QA commands `pnpm tokens:build` and `pnpm complete-check`.
- System impact: `Layout` and the shared `Button` primitive are reused by Setup and Match End, so PBW-61 must scope visual changes to Active Match instead of retuning global defaults. The scoreboard height, sets width, and display-score tokens are currently only consumed by active-match styles, so those token changes are low-risk. `src/components/ActiveMatchScreen/ActiveMatchScreen.module.css` also references a non-existent `--app-screen-shell-body-height`, so the layout refactor should replace that dead variable with an existing shell sizing token instead of carrying the bug forward.

## Chosen Approach

- Proposed solution: Use a small, screen-scoped refactor: update only the active-match-specific source tokens that are already isolated to this screen, let `Layout` read background values from CSS custom properties while keeping today’s defaults for Setup and Match End, simplify `TeamPanel` to the exact Pencil structure, remove `InfoCard` from Active Match composition, and restyle the existing match action buttons with dedicated Active Match classes rather than adding new reusable variants.
- Justification for simplicity: This reuses the current component tree, `Layout` API, generated token pipeline, and button semantics while avoiding new background props, new button variants, or a separate game-screen shell component. Rejected alternatives: adding a specialized `Layout` prop matrix for gradients, creating dedicated `RevertButton` or `FinishButton` production components, or globally changing semantic background tokens that would also alter Setup and Match End.
- Components to be modified/created: Modify `design-tokens/base/dimension.tokens.json`, `design-tokens/base/font.tokens.json`, `design-tokens/semantic/typography.tokens.json`, and regenerated `design-tokens/dist/variables.css`; modify `src/components/Layout/Layout.module.css`; modify `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `src/components/ActiveMatchScreen/ActiveMatchScreen.module.css`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.tsx`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.module.css`, and `src/components/ActiveMatchScreen/SetsCard/SetsCard.module.css`; update `test/components/ActiveMatchScreen/ActiveMatchScreen.browser.test.tsx` and `test/components/ActiveMatchScreen/TeamPanel.browser.test.tsx`. `InfoCard` source files stay in place unless a stale import/comment needs cleanup.
