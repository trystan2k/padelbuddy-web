## Chosen Approach
- Proposed solution: Use a minimal manual bootstrap aligned to the existing repo docs and constraints instead of dropping in a large generated scaffold. Keep each Linear sub-issue narrowly scoped: `PBW-19` defines the package/tooling surface, `PBW-21` establishes structure/config, `PBW-20` wires the minimal TanStack Start app shell, `PBW-22` adds the styling foundation, and `PBW-23` adds the smallest smoke-test and QA baseline needed to prove the bootstrap is sound.
- Justification for simplicity: This is simpler than a full generator-first approach because it avoids template churn, unneeded SSR/server files, and cleanup from generic starter content that does not match the client-only requirement. It is also safer than trying to set up the whole quality stack and UI styling before the app can boot. Rejected approaches: (1) full scaffold import then trim, because it adds cleanup risk and can accidentally preserve server-oriented defaults; (2) over-scoping the parent issue into CI, PWA, and full feature architecture, because that expands beyond bootstrap and creates unnecessary failure points.
- Components to be modified/created: `package.json`, `pnpm-lock.yaml`, `.npmrc` if needed, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `.oxlintrc.json`, `.oxfmtrc.json`, optional `app.config.*` or TanStack config files required by the chosen Start setup, `src/router.tsx`, `src/routes/__root.tsx`, `src/routes/index.tsx`, `src/routeTree.gen.ts` as generated output if committed by project convention, `src/components/BaseUiPreview.tsx`, `src/components/BaseUiPreview.module.css`, `src/styles.css`, `src/core/match/index.ts`, `src/core/match/types.ts`, `test/setup/shared.ts`, `test/setup/browser.ts`, `test/utils/render-component.tsx`, `test/core/match/index.test.ts`, `test/components/BaseUiPreview.browser.test.tsx`, and docs that must be reconciled with the real baseline.
