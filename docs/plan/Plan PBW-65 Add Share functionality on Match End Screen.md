## Task Analysis

- Main objective: Deliver `PBW-65` by completing `PBW-66` and `PBW-67`: turn the existing Match End topbar share placeholder into a real action that captures the full Match End layout (`TopBar` + body + `MatchStatsCard` footer), shares the result through the Web Share API with text plus image, and falls back to downloading a PNG when sharing is unavailable, all while preserving the Pencil-driven Match End visual design.
- Identified dependencies: Reuse the existing Match End seams in `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/MatchEndScreen.module.css`, and `src/components/MatchEndScreen/view-model.ts`; reuse the existing `TopBar` right-side children slot in `src/components/ui/TopBar/TopBar.tsx` without changing its API; make the capture target the `Layout` root in `src/components/Layout/Layout.tsx` because the current `data-testid="match-end-screen"` sits on the inner `.content` node and excludes the header/footer; add runtime dependency changes in `package.json` and `pnpm-lock.yaml`; add localized strings in `public/locales/en.json`, `public/locales/es.json`, and `public/locales/pt.json`; extend browser/unit coverage in `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx` and `test/components/MatchEndScreen/view-model.test.ts`.
- System impact: The behavior is mostly screen-local, but it introduces one new runtime dependency (`modern-screenshot`) and one small shared-shell change so `MatchEndScreen` can reference the `Layout` root for full-screen capture. The main non-obvious risk is the Web Share capability matrix: some browsers expose `navigator.share` but cannot share files, so the implementation must branch cleanly between file sharing and PNG download without regressing accessibility or leaving the share button stuck in a loading state.

## Chosen Approach

- Proposed solution: Keep the feature scoped to Match End by adding a dedicated hook such as `src/components/MatchEndScreen/useMatchEndShare.ts` that receives the rendered Match End root element plus the already-computed summary data, uses `domToBlob` from `modern-screenshot` to capture the `Layout` root, builds a localized share payload from the existing Match End view-model output, calls `navigator.canShare({ files })` and `navigator.share()` when file sharing is supported, and otherwise downloads the captured PNG through an object URL fallback. Wire this hook into the existing topbar share pill so PBW-66 stays a small integration task on top of PBW-67.
- Justification for simplicity: This avoids a global share service, avoids new TopBar API work that PBW-58 already solved, and keeps the screenshot/share logic close to the only screen that needs it. The simplest shared change is to expose the `Layout` root element for capture rather than wrapping the route in extra DOM or relying on brittle `document.querySelector` lookups. Rejected approaches: a cross-app sharing abstraction before there is a second use case, a text-only share fallback when file sharing is unsupported, and a query-selector-based capture path tied to CSS/test IDs.
- Components to be modified/created: Modify `package.json`, `pnpm-lock.yaml`, `src/components/Layout/Layout.tsx`, `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/MatchEndScreen.module.css`, `src/components/MatchEndScreen/view-model.ts`, `public/locales/en.json`, `public/locales/es.json`, `public/locales/pt.json`, `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx`, and `test/components/MatchEndScreen/view-model.test.ts`; create `src/components/MatchEndScreen/useMatchEndShare.ts` if the share logic is kept as a screen-local hook, plus a tiny companion helper only if filename/download code becomes noisy enough to deserve extraction.

## Implementation Steps

1. Make the full-screen capture target explicit before wiring any sharing logic. In `src/components/Layout/Layout.tsx`, expose the root `<main>` element to consumers with the same DOM-ref pattern already used by shared UI primitives (`Button`, `Spinner`) so `MatchEndScreen` can hold a stable ref to the real `Layout` root. In `src/components/MatchEndScreen/MatchEndScreen.tsx`, move `data-testid="match-end-screen"` from the inner `.content` div onto `Layout` itself and keep the inner content structure unchanged. Checkpoint: the capture target now includes header, body, and footer without adding a wrapper element. Mitigation: if forwarding the ref through `Layout` causes unexpected typing churn, fall back to a single screen-local wrapper around `Layout` instead of broadening the shared shell API further.
2. Add the minimal runtime dependency and screen-local sharing hook. Install `modern-screenshot` as a production dependency in `package.json` and update `pnpm-lock.yaml`. Create `src/components/MatchEndScreen/useMatchEndShare.ts` that accepts the capture ref, `matchId`, and the share-relevant summary data from `MatchEndScreen`. Keep the first implementation on the simple `domToBlob(node)` path instead of worker/context setup; only opt into worker mode later if validation shows capture latency or image quality problems. The hook should own `isSharing`, a normalized error state, and a single `handleShare()` entry point so PBW-66 only needs to bind button props.
3. Reuse existing Match End view-model data for the share payload instead of re-deriving match facts from raw route props. Extend `src/components/MatchEndScreen/view-model.ts` only where it adds real value, for example by adding a tiny helper that derives winner/loser or set-win counts from the existing `MatchEndScreenSummary` when building share text. In `src/components/MatchEndScreen/MatchEndScreen.tsx`, pass the already-computed `summary`, `durationValue`, and translated labels into the new hook so the share copy stays consistent with what the user sees on screen. Add the required i18n keys in `public/locales/en.json`, `public/locales/es.json`, and `public/locales/pt.json`: at minimum `match.end.actions.sharing` plus a `match.end.share.*` namespace for the localized text template, the generic failure message, and any status text used by the fallback/download path. Include a separate early-finish/tie string so `isFinishedEarly` matches the existing view-model behavior.
4. Wire PBW-66 into the current topbar share button and keep the interaction accessible. In `src/components/MatchEndScreen/MatchEndScreen.tsx`, remove the hard-coded `disabled` attribute, connect `onClick` to `handleShare`, and disable the button only while `isSharing` is true so duplicate captures cannot run. In `src/components/MatchEndScreen/MatchEndScreen.module.css`, preserve the existing pill styling from PBW-73 but restore interactive affordances (`cursor`, hover/focus states) for the idle state and add a loading modifier that keeps the button width stable while capture is in progress. Prefer a simple loading treatment that stays accessible inside a button, such as swapping the label from `match.end.actions.share` to `match.end.actions.sharing` and optionally rendering a small inline loader only if it does not create nested live regions. Treat `AbortError` from a dismissed share sheet as a quiet cancel, but surface unexpected failures through a localized inline status or `role="alert"` region so the feature fails gracefully without relying only on `console.error`.
5. Implement the Web Share and PNG download capability matrix inside `src/components/MatchEndScreen/useMatchEndShare.ts`. After capture, create a PNG `File` (for share) and keep the original `Blob` (for fallback download), then build a payload that includes both `text` and `files`. Prefer `navigator.canShare({ files })` when available; if `navigator.share` is missing, `canShare` is false, or the browser exposes share but rejects file payloads, fall back to downloading the PNG via `URL.createObjectURL`, a temporary anchor, and `URL.revokeObjectURL`. Use a stable filename such as `padel-buddy-match-<matchId>.png` so the fallback is predictable without adding a new sanitization subsystem. During implementation, verify one subtle edge case: because the share button lives inside the captured topbar, the loading treatment can accidentally appear inside the exported image; if that happens, use `modern-screenshot` clone/filter options or a capture-only data attribute to keep the exported button in its resting visual state while the live UI still shows loading.
6. Add focused automated coverage where the feature already lives, then finish with the existing QA pipeline. Update `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx` to replace the old disabled-placeholder assertion with behavior tests for: the enabled topbar share button, loading-state lockout while capture is running, `navigator.share` receiving localized `text` plus a PNG `File` when file sharing is supported, and download fallback when `navigator.share` or file sharing is unavailable. Extend `test/components/MatchEndScreen/view-model.test.ts` only for any new pure helper that shapes share text inputs, especially winner/loser and early-finish cases. Keep Playwright scope unchanged unless browser tests prove insufficient for the capability matrix, then run `pnpm complete-check` as the final regression gate.

## Validation

- Success criteria: On the Match End route, the topbar share pill is visible on the right, keyboard-clickable, and no longer permanently disabled; clicking it captures the full Match End layout root (header, body, and footer), shows a temporary loading state, shares a PNG plus localized text when file sharing is supported, falls back to downloading a PNG when sharing is unavailable, resets cleanly on user cancel or failure, and leaves all locales/tests/build checks green under `pnpm complete-check`.
- Checkpoints: Pre-implementation check - confirm `Layout` already owns the correct full-screen DOM root and `TopBar` needs no API change because its children slot is already in place. Mid-implementation correctness check - verify `domToBlob` receives the `Layout` root rather than the old `.content` node, the button cannot be clicked twice while `isSharing` is true, and the share payload uses the existing Match End summary data instead of recomputing match facts from raw route props. Capability check - validate the three main branches: file-sharing browsers (`navigator.share` + `files`), share-capable browsers without file support (download fallback), and canceled shares (`AbortError` does not show a hard failure). Accessibility/error check - ensure the loading label is announced correctly, any failure state reaches a localized live region or alert, and unsupported browsers still complete a useful action by downloading the PNG. Regression check - if the `Layout` ref change or screenshot library introduces unexpected shell regressions, roll back to a single screen-local capture wrapper rather than widening the shared API further, then rerun `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx` and `pnpm complete-check`.
