## Task Analysis

- Main objective: Deliver `PBW-36` as a dedicated finish-route experience at `/match/finish/:id`, following the Pencil `Game End Screen` in `docs/design/padelbuddyweb.pen` (node `48SbC`) with design tokens from `design-tokens/`. The finish screen must show the winner announcement, final score / set summary, a frozen match-length/statistics summary, `New Match`, and a real `Continue` action that returns players to `/match/:id` for the same match so they can continue indefinitely.
- Identified dependencies: Reuse the existing match lifecycle from `PBW-11`, `PBW-12`, `PBW-14`, `PBW-15`, `PBW-16`, and `PBW-35`. The key files/modules to inspect/update are `src/routes/match.$id.tsx`, `src/routes/match.finish.$id.tsx`, `src/routes/-match-route-state.ts`, `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `src/components/ActiveMatchScreen/useMatchSession.ts`, `src/components/ActiveMatchScreen/useMatchTimer.ts`, `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/view-model.ts`, `src/components/ui/Card/Card.tsx`, `src/components/ActiveMatchScreen/SetsCard/SetsCard.tsx`, `src/components/ActiveMatchScreen/InfoCard/InfoCard.tsx`, `src/lib/current-match/persistence.ts`, `src/lib/current-match/indexed-db.ts`, `src/lib/current-match/session.ts`, `src/core/match/replay.ts`, locale files under `public/locales/`, and tests under `test/components/`, `test/routes/`, `test/current-match/`, and `e2e/`.
- System impact: The dedicated finish-route architecture stays approved, but three refinements materially affect the data contract and component structure. First, match duration on the finish page must freeze when the match completes, so the current `startedAt -> Date.now()` calculation is no longer sufficient on its own. Second, continuing from the finish page must resume the timer from the stored finished duration without counting time spent paused on the finish page, which requires a minimal session/persistence adjustment. Third, the finish page should be refactored to follow the same composition pattern as the active page by creating focused wrapper components built on the shared `Card` component rather than styling page-level custom cards directly.

## Chosen Approach

- Proposed solution: Keep `/match/$id` as the active route and `/match/finish/$id` as the completed route. Extend the singleton current-match record with one minimal timer-freeze field, preferably an optional `finishedAt` timestamp captured when a match first becomes completed. Use `finishedAt - startedAt` as the frozen finished duration on the finish screen. When the user presses `Continue`, reuse `continuePlaying()` but update the session commit so it clears `finishedAt` and rewrites `startedAt` to `Date.now() - frozenElapsedMs`, which resumes the active timer from the finished duration instead of from zero and without counting paused time on the finish page.
- Justification for simplicity: This preserves the existing singleton persistence model, avoids a new timer subsystem, and reuses the already-existing continuation domain flow (`continueMatch` / `continuePlaying`) instead of inventing a separate resume mechanic. For the UI refactor, the simplest maintainable approach is to mirror the active-page pattern with focused components such as `WinnerCard`, `MatchSummaryCard`, and `MatchStatsCard` that each compose the shared `Card` base plus local CSS, rather than leaving all end-screen card styling embedded in `MatchEndScreen`.
- Components to be modified/created: Likely update `src/lib/current-match/persistence.ts`, `src/lib/current-match/indexed-db.ts`, `src/lib/current-match/session.ts`, `src/components/ActiveMatchScreen/useMatchTimer.ts`, `src/components/ActiveMatchScreen/useMatchSession.ts`, `src/routes/match.$id.tsx`, `src/routes/match.finish.$id.tsx`, `src/routes/-match-route-state.ts`, `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/view-model.ts`, and create focused wrappers such as `src/components/MatchEndScreen/WinnerCard/`, `src/components/MatchEndScreen/MatchSummaryCard/`, and `src/components/MatchEndScreen/MatchStatsCard/` built on `Card`. Likely update locale files and tests in `test/components/MatchEndScreen/`, `test/components/ActiveMatchScreen/`, `test/routes/`, `test/current-match/`, and the PBW-36 e2e flow.

## Implementation Steps

1. Reconfirm the route contract and UI composition targets before editing: `/match/$id` remains active-only and `/match/finish/$id` remains finish-only. Align the screen structure to the Pencil end screen by keeping the hero region in the body, moving the stats card to the footer, enlarging the trophy treatment, and refactoring the finish page so the page component mainly composes focused child cards instead of owning all card-specific styling.
2. Make the minimum timer persistence change needed for correct finished/resumed duration behavior: extend the singleton current-match record with an optional `finishedAt` timestamp, thread it through the persistence decode/create helpers and current-match session snapshot types, and capture it when a scoring mutation first transitions the projection to `completed`. Prefer keeping this as the only new timer-related field so the change stays narrow and compatible with the existing persistence architecture.
3. Freeze finished duration from persisted data rather than live wall-clock time: update the finish-route summary/view-model path so the displayed match length uses `finishedAt - startedAt` when the match is completed, not `Date.now() - startedAt`. This ensures the finish page shows the duration of the finished game and does not keep incrementing across refreshes, route revisits, or time spent on the finish page.
4. Update continuation so resumed active play starts from the frozen finished length: reuse `continuePlaying()` as the behavior trigger, but adjust the session mutation to compute the frozen elapsed duration from `finishedAt - startedAt`, rewrite `startedAt` to `Date.now() - frozenElapsedMs`, clear `finishedAt`, persist the updated record, and then navigate back to `/match/$id`. This is the minimum change that makes the resumed active-match timer continue from the stored finished duration without restarting at zero or counting paused finish-screen time.
5. Keep route-state resolution aligned with the timer and continuation changes: active route logic should still redirect only genuinely completed matches to `/match/finish/$id`, but once `Continue` persists endless-play setup and clears `finishedAt`, the active route should resolve as in-progress and stay on `/match/$id`. The finish route should redirect back to `/match/$id` whenever the persisted record for that `matchId` is no longer completed, which naturally covers refreshes after continuing.
6. Refactor the finish page to reuse existing UI patterns and the shared `Card` component: follow the same pattern already used on the active page with focused card wrappers. Create dedicated components such as `WinnerCard`, `MatchSummaryCard`, and `MatchStatsCard` that each wrap `Card` with local markup/styles, then let `MatchEndScreen` compose those pieces alongside `Layout` and `TopBar`. Keep card styling localized to those wrapper components so the finish page stops duplicating page-level card treatments directly.
7. Preserve the requested behavior changes while simplifying page-level responsibilities: `MatchEndScreen` should mainly wire together the localized header, body cards, footer stats card, `New Match`, and `Continue` handlers. Match-length formatting can remain in a small shared helper, but card content/layout belongs in the focused wrappers, mirroring the separation already present on the active page with `SetsCard` and `InfoCard`.
8. Update automated coverage around the new timer and composition behavior: add tests that prove the finish-screen duration does not increment after completion, that `Continue` resumes the active timer from the stored finished duration, and that refreshes after continue stay on `/match/$id`. Update component tests so the finish page is composed from focused card wrappers and footer stats rather than page-level custom cards, and extend e2e coverage so a match completed at e.g. 15 minutes shows `15 min` on the finish page, remains `15 min` while paused there, and resumes from `15 min` after `Continue`. Finish with `pnpm complete-check`.

## Validation

- Success criteria: After a match completes, the app navigates to `/match/finish/$id`, shows a Pencil-aligned finish screen composed from focused card wrappers built on the shared `Card` component, and displays a frozen match length derived from the finished game rather than a still-running clock. Pressing `Continue` mutates the same singleton current-match record into endless play, preserves the current actions/setup, rewrites timer state so `/match/$id` resumes from the stored finished duration, and does not restart the timer from zero. Pressing `New Match` still clears the record and returns home. `pnpm complete-check` passes.
- Checkpoints: Pre-implementation check - confirm the current finish summary still derives duration from `Date.now()` and that card styling is still page-local instead of wrapper/component-based. During implementation check - verify the persistence/session layer stores `finishedAt` on completion, clears it on continue, and recomputes `startedAt` from the frozen elapsed duration before saving. Route/timer check - refresh `/match/finish/$id` after completion and confirm the displayed duration stays fixed; then continue and confirm `/match/$id` shows the timer resuming from the stored finished length. Composition check - confirm `MatchEndScreen` becomes a page-level composer that reuses focused `Card`-based wrappers in the same spirit as the active page's `SetsCard` and `InfoCard`. Regression check - confirm automatic handoff to `/match/finish/$id` still works, repeated refreshes after continue remain on the active route, and the new tests cover both frozen-duration and resumed-duration behavior.
