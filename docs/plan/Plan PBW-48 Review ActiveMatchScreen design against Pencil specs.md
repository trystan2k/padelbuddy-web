## Task Analysis

- Main objective: Bring `src/components/ActiveMatchScreen/` into pixel-level alignment with Pencil node `VSRKf` ("Game Screen") by correcting layout, overlay positioning, ordering, spacing, typography, sizing, colors, radius, gradients, and button/indicator behavior without changing match logic beyond the accepted UI rules.
- Identified dependencies: No blocking Linear dependencies per intake; implementation must reuse existing `Layout` max-width behavior, Active Match subcomponents (`ActiveMatchScreen`, `TeamPanel`, `SetsCard`, `InfoCard`), shared primitives (`Button`, `Card`, `Chip`), locale strings in `public/locales/*.json`, and design tokens from `design-tokens/` plus Pencil values from `docs/design/padelbuddyweb.pen`.
- System impact: Likely touches `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `src/components/ActiveMatchScreen/ActiveMatchScreen.module.css`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.tsx`, `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.module.css`, `src/components/ActiveMatchScreen/SetsCard/SetsCard.tsx`, `src/components/ActiveMatchScreen/SetsCard/SetsCard.module.css`, possibly `src/components/ActiveMatchScreen/InfoCard/InfoCard.module.css`, browser tests under `test/components/ActiveMatchScreen/`, and locale files if set-row labels are localized.

## Chosen Approach

- Proposed solution: Start with a Pencil/design-token audit first, then make screen-scoped layout and styling corrections in `ActiveMatchScreen` and its local subcomponents, using shared primitives only where they still match the spec. For mismatches caused by generic `Card`/`Chip`/`Button` styling, prefer local class overrides or small markup adjustments over global primitive changes.
- Justification for simplicity: This keeps the fix isolated to the active-match surface, avoids redesigning shared UI primitives for one screen, and matches the acceptance criteria directly. Rejected alternatives: (1) global token or primitive changes first, which risks regressions in SetupScreen and other surfaces; (2) a full bespoke rewrite of the screen, which would create unnecessary churn when the structure already exists.
- Components to be modified/created: Modify `ActiveMatchScreen` layout/composition, `TeamPanel` serve-indicator presentation, `SetsCard` labels and row styling, `InfoCard`/timer ordering and overlay styling, relevant browser tests, and locale files only if the final set-row labels must remain translated. No new architectural modules should be needed.

## Implementation Steps

1. Phase 1 - Audit Pencil and token values before coding: confirm exact measurements from `VSRKf` and related nodes (`pGBiU`, `cOPm9`, `5ynmX`, `ilG6v`, `Lwif8`) against `design-tokens/` and the current CSS so the implementation uses the right widths (`1024`, `452`, `180`, `177`, `220`), padding, type sizes, radii, and colors. Check whether any discrepancy comes from shared primitives versus local screen CSS before changing code.
2. Phase 2 - Fix the screen shell and overlay layout in `ActiveMatchScreen`: keep the screen constrained to the same `1024px` body width as SetupScreen, make the score area a positioned container, and absolutely anchor the Set card, Timer chip, and Info card between the two team panels in Pencil order (`Set`, `Timer`, `Info`). Add responsive fallback rules so overlays collapse cleanly below tablet widths. Risk/mitigation: absolute positioning is the highest regression risk; keep the change contained to screen-local CSS and validate at `1024px`, tablet, and narrow mobile widths immediately after this step.
3. Phase 3 - Correct the local component visuals to match the approved defaults and Pencil intent: update `SetsCard` to show `Set 1`, `Set 2`, and `Current`, remove the green completion tick, remove any extra current-dot treatment if it conflicts with the Pencil row styling, and align row typography/spacing to the Pencil values (`14px` Inter labels, `24px` Outfit scores, `6px` row gap). Update `TeamPanel` so the serve indicator is decorative and slimmer with no visible text, while preserving an accessible hook if needed for tests/screen readers. Make the finish button always active across match states unless an actual hidden rule is found during code review; current inspection only shows a UI disable guard tied to `winner`, so plan to remove that gating. If localized labels are required, add or adjust keys in `public/locales/en.json`, `public/locales/es.json`, and `public/locales/pt.json` rather than hardcoding English.
4. Phase 4 - Update tests and run QA in increasing scope: first update the affected browser tests in `test/components/ActiveMatchScreen/ActiveMatchScreen.browser.test.tsx` and `test/components/ActiveMatchScreen/SetsCard.browser.test.tsx` for the new finish-button enabled behavior, new set labels, absence of winner tick, and revised serve-indicator expectations; then run targeted Active Match browser tests; then run `pnpm complete-check`; finally do manual visual verification against the Pencil screenshot at `1024px` and responsive edge cases. Risk/mitigation: there is no dedicated screenshot snapshot harness in the existing tests, so use manual screenshot comparison or a temporary local browser capture rather than introducing new visual-regression infrastructure inside this task.

## Validation

- Success criteria: The rendered Active Match screen matches Pencil node `VSRKf` in structure and styling at the `1024px` target width; the overlays sit between the score panels in the order `Set`, `Timer`, `Info`; the serve indicator is visual-only; the finish button is enabled outside transient async handling; set rows read `Set 1`, `Set 2`, `Current` with corrected typography and no green tick; existing Active Match interactions still behave correctly.
- Checkpoints: (a) Pre-implementation: confirm Pencil measurements and token mappings before editing; (b) During layout work: verify overlay positions in the DOM/CSS at `1024px` before touching subcomponent typography; (c) During component refinement: verify each subcomponent against its Pencil node and update browser tests alongside markup changes; (d) Post-implementation: run targeted Active Match browser tests, then `pnpm complete-check`, then manual visual checks at `1024px`, tablet, and mobile widths to catch clipping/overlap regressions.
