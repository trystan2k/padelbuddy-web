## Task Analysis

- Main objective: Implement PBW-99 by adding a local-first Game History flow that persists completed matches in IndexedDB, exposes a `/history` browse/rematch surface from Setup, and lets `/match/finish/$id` render immutable history snapshots via `?from=history` without disturbing the active-match flow.
- Identified dependencies: Reuse the shared IndexedDB bootstrap in `src/lib/persistence/indexed-db.ts` and the current match data shape in `src/lib/current-match/*`; reuse route/search patterns from `src/routes/index.tsx` and `src/routes/match.finish.$id.tsx`; reuse shell/UI patterns from `src/components/SetupScreen/SetupScreen.tsx`, `src/components/MatchEndScreen/*`, `src/components/Layout/Layout.tsx`, and `src/components/ui/TopBar/TopBar.tsx`; update i18n in `src/lib/i18n/locales/{en,es,pt}.ts`; add new coverage alongside `test/current-match`, `test/routes`, and browser component suites. Linear dependency status was not included in the provided issue details, so this plan assumes PBW-99 has no unresolved blockers.
- System impact: This feature changes the persistence schema (database version `6 -> 7`), current-match completion flow, home/search-param handling, a new route/screen, match-end action rendering, and regression coverage. The highest-risk seams are avoiding overengineered IndexedDB changes, keeping history viewing isolated from the current-match store, and ensuring rematch prefills stay ephemeral instead of silently overwriting saved setup preferences.

## Chosen Approach

- Proposed solution: Use a dedicated `match-history` object store keyed by `matchId`, storing the same validated finished-match snapshot shape already used by current-match persistence (`setup`, `actions`, `startedAt`, `finishedAt`) so history entries can be replayed without a second summary table. Auto-save to history inside `src/lib/current-match/session.ts` whenever a snapshot becomes finished, then prune overflow items in the same write transaction by sorting `finishedAt` in memory and deleting anything beyond 100. Add a new `src/routes/history.tsx` + `HistoryScreen` that loads the list, renders the Pencil-designed shell with `TopBar`, count chip, list rows, and footer Back button, and handles View / Play Again / Delete using existing router and button patterns. Use search params, not persistent setup storage, for cross-screen intent: `/?team1=...&team2=...` for Play Again prefill and `/match/finish/$id?from=history` for history-mode summary rendering.
- Justification for simplicity: This deliberately rejects three heavier options: (1) adding IndexedDB key paths, indexes, or a second summary store when the cap is only 100 records and `getAll()` + in-memory sort is fast enough; (2) copying history data into `current-match` before viewing it, which would couple browsing to active-match state and risk clobbering real progress; and (3) persisting Play Again names into setup preferences, which would make a one-off rematch intent mutate the user’s saved defaults. The chosen path keeps new logic confined to one persistence module, one route, and narrow action-area updates on existing screens.
- Components to be modified/created: Modify `src/lib/persistence/indexed-db.ts`, `src/lib/current-match/session.ts`, `src/routes/index.tsx`, `src/components/HomeScreen/HomeScreen.tsx`, `src/components/SetupScreen/SetupScreen.tsx`, `src/components/SetupScreen/SetupScreen.module.css`, `src/components/SetupScreen/useSetupForm.ts`, `src/routes/match.finish.$id.tsx`, `src/routes/-route-utils.tsx`, `src/components/MatchEndScreen/MatchEndScreen.tsx`, `src/components/MatchEndScreen/WinnerCard.tsx`, `src/components/MatchEndScreen/WinnerCard.module.css`, and `src/lib/i18n/locales/{en,es,pt}.ts`. ## Implementation Steps

1. Add the persistence foundation for history storage. In `src/lib/persistence/indexed-db.ts`, bump `persistenceDatabaseVersion` from `6` to `7`, export `matchHistoryObjectStoreName = 'match-history'`, and keep store creation plain so the shared bootstrap does not gain new keyPath/index abstractions. Create `src/lib/match-history/persistence.ts` with a `MatchHistoryRecord` based on the current-match record shape plus required `finishedAt`, reusing the existing current-match validation/replay helpers where possible so malformed or unfinished payloads are rejected consistently. Then create `src/lib/match-history/indexed-db.ts` with `saveMatchHistory`, `listMatchHistory`, `loadMatchHistoryById`, and `deleteMatchHistory`. `saveMatchHistory` should `put(record, matchId)`, call `getAll()` in the same `readwrite` transaction, sort by `finishedAt`, and delete overflow entries so the 101st save prunes only the oldest completed record. This covers Acceptance Criteria 1, 2, 7, and 9. Mitigation note: keep pruning isolated to the new history module so any bug can be rolled back without altering current-match persistence semantics.
2. Wire auto-save at the existing match-end seam instead of a UI effect. In `src/lib/current-match/session.ts`, extend `commitSnapshot()` so any committed snapshot with a numeric `finishedAt` also upserts that finished record into `match-history`. Because the history store key is `matchId`, repeated writes for the same match update one record instead of creating duplicates, which keeps automatic completion and manual “Finish Match” aligned while still supporting “Continue” flows. Keep this write in the session layer so persistence completes before navigation to `/match/finish/$id`, avoiding route-level races. This covers Acceptance Criterion 3.
3. Add route/search plumbing for rematch prefills and history-mode finish loading. In `src/routes/index.tsx`, extend `validateSearch()` to accept optional `team1` / `team2` alongside the existing `error` param, and pass those values through `src/components/HomeScreen/HomeScreen.tsx` into `SetupScreen`. In `src/components/SetupScreen/useSetupForm.ts`, add a small non-persisting prefill API (or equivalent prop-driven effect) that updates local team names and touched refs without calling `saveSetupPreferenceSlice`; then update `SetupScreen.tsx` to apply the search-param values when coming from Play Again. In `src/routes/match.finish.$id.tsx`, add `validateSearch()` for `from=history`, pass that state into the component, and update `src/routes/-route-utils.tsx` so `from=history` makes the finish route load the record from `match-history` as the authoritative source instead of relying on current-match redirects. That explicitly handles the edge case where the active-match store is empty or holds a different match, and it keeps history viewing read-only. This covers Acceptance Criteria 10, 11, and 12 plus the loader edge-case requirement. Mitigation note: gate the new loader branch strictly behind `from=history` so the existing active-match route behavior remains the rollback-safe default.
4. Update Setup entry points to expose History and preserve the existing screen structure. In `src/components/SetupScreen/SetupScreen.tsx` and `src/components/SetupScreen/SetupScreen.module.css`, move the existing Remote Configuration button into the right column, add a new full-width History button in the left column, and keep Store buttons beneath the left-column actions using the existing `Button` + `Layout` patterns instead of introducing new bespoke controls. Wire History to `navigate({ to: '/history' })`, keep the Start Match flow unchanged, and ensure the Play Again prefill remains ephemeral rather than being written into setup storage automatically. This covers Acceptance Criteria 4 and 5.
5. Create the new History route and screen using existing shell primitives and the Pencil layout. Create `src/routes/history.tsx` with a loader that returns the latest list from `match-history` and a fresh-on-entry configuration (`staleTime: 0`) so the route always reflects the newest saved matches. Build `src/components/HistoryScreen/HistoryScreen.tsx` + `.module.css` with `Layout`, `TopBar`, and CSS Modules powered by the generated design tokens, following `docs/design/padelbuddyweb.pen`: header title/subtitle (“Match History”), passive count chip, scrollable body, and footer Back button to return home. Each row should render team names, localized finished date, and a final sets summary derived from replayed match projection; if the Pencil row still includes a games column, derive it from the same projection instead of storing extra fields. Add View, Play Again, and Delete actions using existing button variants. Delete should remove the record from IndexedDB and local screen state; Play Again should navigate to `/?team1=...&team2=...`; View should navigate to `/match/finish/$id?from=history`. This covers Acceptance Criteria 6, 7, 8, 9, 10, 11, and 13. Mitigation note: keep the first implementation to a single screen component unless the row markup becomes unmanageably large, then extract only the row subcomponent.
6. Make Match End history-aware without forking the full screen. Update `src/components/MatchEndScreen/MatchEndScreen.tsx` to accept an `isFromHistory` (or `source`) prop from the route and pass that state down to `WinnerCard`. Then update `src/components/MatchEndScreen/WinnerCard.tsx` + `.module.css` so default mode keeps the existing `New Match` + `Continue` actions, while history mode renders a single `Back` action that returns to `/history`. Do not fork the summary cards, share button, or layout shell; keep only the action area mode-aware so the existing Match End design and behavior remain shared. This specifically covers Acceptance Criterion 12 while preserving Acceptance Criterion 11.
7. Localize the new strings, add focused regression coverage, and close with project QA. Update `src/lib/i18n/locales/en.ts`, `es.ts`, and `pt.ts` with history/header/footer/button/empty-state/match-count copy plus the Match End `Back` label and any rematch/search-param text needed by the new flows. Add tests for: history persistence save/list/delete and 101st-item pruning (`test/match-history/indexed-db.test.ts` or the matching browser persistence file if real IndexedDB is required), home-route search parsing in `test/routes/index.test.tsx`, `from=history` parsing and history-loader fallback in `test/routes/match.finish.$id.browser.test.tsx`, Setup button placement/navigation in `test/components/SetupScreen/SetupScreen.browser.test.tsx`, Match End history-mode Back action in `test/components/MatchEndScreen/MatchEndScreen.browser.test.tsx`, and History screen row/actions behavior in `test/components/HistoryScreen/HistoryScreen.browser.test.tsx`. Finish with `pnpm complete-check`, and verify that the generated `src/routeTree.gen.ts` updates automatically from the new route file instead of being hand-edited.
