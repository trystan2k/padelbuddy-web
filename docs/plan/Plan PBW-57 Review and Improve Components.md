## Chosen Approach

- Proposed solution: Implement PBW-58, PBW-59, and PBW-60 sequentially with the smallest surface-area changes that match the accepted behavior. For PBW-58, make `TopBar` generic by rendering a right-side slot via `children` and keep the locale dropdown logic reusable by exporting a `TopBarLocaleSelector` helper from the same module. For PBW-59, extend `MatchSetup` and `SetupFormData` with countdown settings, keep those settings persisted in the existing current-match payload, and enhance `useMatchTimer` so it derives either count-up or countdown output directly from `startedAt`, `finishedAt`, and the persisted setup without introducing any new global state. For PBW-60, add `servingIndicatorEnabled` to the same setup path, disable-but-preserve the existing First Server selection in Setup when the toggle is off, and hide the active-match serve bar in the UI without altering the serving-order domain logic.
- Justification for simplicity: This approach reuses the current screen composition, current-match persistence, and domain setup validation patterns instead of introducing a new timer store, route-level header abstraction, or derived-state flag machinery. Rejected alternatives: (1) adding multiple special-purpose `TopBar` variant props for locale, timer, and future badges, which would hardcode PBW-57 behavior into a supposedly reusable header; (2) creating a separate countdown session/state machine, which would duplicate data already derivable from timestamps; (3) changing match engine or `derived-state.ts` to support the serving-indicator toggle, which is unnecessary because the domain can keep calculating `servingTeam` even when the UI chooses not to show it.
- Components to be modified/created: Modify `src/components/ui/TopBar/TopBar.tsx`, `src/components/ui/TopBar/TopBar.module.css`, and `src/components/ui/TopBar/index.ts`; modify `src/components/SetupScreen/SetupScreen.tsx`, `src/components/SetupScreen/useSetupForm.ts`, `src/components/SetupScreen/types.ts`, `src/components/SetupScreen/validateSetupForm.ts`, and `src/components/SetupScreen/SetupScreen.module.css`; modify `src/components/ActiveMatchScreen/ActiveMatchScreen.tsx`, `src/components/ActiveMatchScreen/ActiveMatchScreen.module.css`, `src/components/ActiveMatchScreen/useMatchTimer.ts`, and `src/components/ActiveMatchScreen/TeamPanel/TeamPanel.tsx`; modify `src/components/MatchEndScreen/MatchEndScreen.tsx`; modify `src/core/match/types.ts`, `src/core/match/validation.ts`, `src/core/match/index.ts`, and `src/lib/current-match/persistence.ts`; update `public/locales/en.json`, `public/locales/es.json`, and `public/locales/pt.json`; update the affected browser, unit, integration, and Playwright tests. No new production file should be introduced unless extracting a tiny helper becomes necessary to keep `TopBar.tsx` or `useMatchTimer.ts` readable.
