## Task Analysis

- Main objective: Deliver `PBW-9` by turning the current bootstrap-quality baseline into a reliable local quality harness that covers linting, formatting, unit tests, browser-mode smoke tests, coverage enforcement, staged-file hooks, and a single documented verification command. Assumptions: `PBW-8` is the only dependency and is already satisfied; this remains a single-package root setup; CI/E2E expansion beyond the local harness is out of scope for this issue.
- Identified dependencies: The repo already contains partial groundwork in `package.json`, `.oxlintrc.json`, `.oxfmtrc.json`, `vitest.config.ts`, `test/setup/shared.ts`, `test/setup/browser.ts`, `README.md`, and bootstrap smoke tests, so the work should refine and complete those patterns instead of replacing them. Additional implementation dependencies will likely be browser-mode and hook packages plus any minimal testing-library utility needed for shared component helpers.
- System impact: This issue will update the package scripts and dependency graph, strengthen repository-wide quality config, add hook files and staged-file automation, and revise the testing/docs surface. Primary risks are (1) keeping `complete-check` aligned with the PRD while avoiding mutating checks in the main verification flow, (2) making browser-mode failures actionable when Playwright browsers are missing, and (3) enforcing global `80%` line/branch coverage without accidentally counting generated files or leaving the bootstrap app under-covered.

## Chosen Approach

- Proposed solution: Evolve the existing root-level tooling into a phased, minimal-quality stack instead of introducing new orchestration layers. Keep Oxlint and Oxfmt as the repo-standard tools, split scripts into explicit fix vs check commands, upgrade Vitest into two named projects (`unit` and `browser`) with shared setup/utilities and global coverage thresholds, add one lightweight browser smoke test alongside the current unit smoke baseline, wire Husky + lint-staged only for fast staged-file checks, and make `pnpm run complete-check` the non-mutating local gate described by the PRD and README.
- Justification for simplicity: This is the simplest effective approach because it reuses the configs and test structure already created in `PBW-8`, keeps all quality tooling at the repo root, and avoids overengineering with extra task runners, custom hook frameworks, or a full Playwright E2E suite. Rejected approaches: (1) layering Turbo/Taskfile-style orchestration on a single-package app, which adds abstraction with no acceptance-criteria benefit; (2) jumping straight to full Playwright E2E infrastructure, which expands beyond the stated browser-mode Vitest harness.
- Components to be modified/created: `package.json`, `pnpm-lock.yaml`, `.oxlintrc.json`, `.oxfmtrc.json`, `vitest.config.ts`, existing `test/setup/*.ts`, new shared helpers under `test/utils/`, at least one `*.browser.test.tsx` smoke test plus any small unit-test alignment updates, `.husky/**`, a lint-staged config file or `package.json` lint-staged block, and `README.md`. If actionable browser-install messaging cannot be expressed cleanly in `package.json` alone, add one small repo script under `scripts/` rather than spreading logic across test files.

## Implementation Steps

1. Audit the current tooling surface against the acceptance criteria, then normalize the root scripts in `package.json` so the repo has clear fix and verification entry points: keep `lint:fix` and `format` for local remediation, add or refine non-mutating `lint` and `format:check`, introduce explicit `test` command, and redefine `pnpm run complete-check` as the required local verification flow from the PRD. Risk/mitigation: changing `complete-check` from the current mutating sequence can surprise contributors, so update the command names first and immediately reflect the new contract in README text.
2. Finalize the Oxlint and Oxfmt baseline without replacing the existing conventions: verify the current ignore patterns still match generated/output files, ensure repo-convention scripts call the tools consistently from the root, and remove any unused or misleading config/dependency pieces only if they no longer contribute to the final workflow. During-implementation check: the clean bootstrap app should pass `pnpm lint`, `pnpm lint:fix`, `pnpm format`, and `pnpm format:check` with no config drift.
3. Upgrade `vitest.config.ts` into the final two-project harness by keeping the current merged Vite pattern, enabling a real browser-mode project, and adding global coverage thresholds for lines and branches at `80`. Prefer the smallest effective dependency set: a Node-based unit project for fast smoke tests, a Playwright-backed browser project for one real browser smoke test, shared setup files under `test/setup/`, and a small wrapper or script that converts the common "browsers not installed" failure into actionable guidance (for example, telling the developer exactly which `playwright install` command to run). Rollback note: if browser-provider wiring destabilizes the config, revert only the provider-specific additions back to the last green unit-test checkpoint before retrying.
4. Add or refine shared test utilities under `test/utils/` so both unit and browser tests use the same rendering/setup conventions where appropriate, then adjust the smoke-test set to prove the harness works in both environments. Keep the utilities intentionally small - for example, a render helper, shared cleanup/bootstrap helpers, or router-aware wrappers - and avoid building a generalized test framework before feature work exists. Risk/mitigation: the bootstrap source may not naturally reach global `80/80` coverage with only two smoke tests, so scope coverage intentionally to maintainable app sources and add the minimum extra smoke assertions needed instead of weakening thresholds.
5. Configure Husky and lint-staged for fast local guardrails only: add the install hook (`prepare`), create a `pre-commit` hook, and run staged-file quality commands that are quick and relevant to modified files. Keep the hook payload limited to lint/format-type checks on staged files, while leaving `pnpm run complete-check` as the full manual pre-PR gate so commits stay fast and the repo avoids duplicate heavy test runs on every commit.
6. Reconcile the documentation with the final implementation by updating `README.md` to match the actual scripts, browser-mode prerequisites, coverage-threshold behavior, and the required `pnpm run complete-check` flow, then perform the final verification pass in the same order contributors will use locally. This final pass should explicitly include the happy path (`pnpm run complete-check`, unit smoke tests, browser smoke tests) and the documented failure path for missing Playwright browsers so reviewers can confirm the messaging is actionable and accurate.
